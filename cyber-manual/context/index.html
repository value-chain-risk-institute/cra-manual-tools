Components are what you know. Functions are where the chain starts.

List the product components and their security properties first; those are yours and nobody derives them. Then the hard part of the template, how much context and how many conditions to write, stops being a judgment call. It is a chain, and each link tells you exactly what belongs in the next.

PC → FCEach function is performed by product components. Tick which ones. A component no function uses is either missing a function or is not worth listing. FC → CCA context component exists only if a function needs it. Walk each function and ask what outside the product it depends on. Each answer is a CC. Nothing else is. CC → CUA condition of use exists only if a context component must satisfy it for a function to be safe. Each answer is a CU, already attached to the CC the template asks for. CU → RIA risk is a condition of use that is not met. Ask what happens if this CU is violated. Each answer is an RI with its damage. diagramThe picture on the right is that chain drawn. It is never made separately. Fix the lists and the diagram fixes itself.
